## 1. 探测背景

需求文档《需求与架构选型 v0.3》依据厂家两份规约文档（RS-Modbus 规约 / 标准 ModBus 规约）做了链路与可行性设计，
但厂家 RS-Modbus 规约文档存在若干可疑点（样例笔误、参数与说明书不一致等）。
本任务要求**绕开文档、直接向设备问询**，确定主机从站口的真实通讯方式，并据此产出可执行的协议文档。

## 2. 探测环境与方法

### 2.1 物理链路

| 项目 | 实测值 |
| --- | --- |
| 串口 | **COM3**（`\Device\Serial4`） |
| 适配器 | **MacroSilicon USB Serial Ports**，USB `VID_345F&PID_3020` |
| 端口历史设置 | `mode COM3` 显示 Baud 19200 / N / 8 / 1（**非当前有效值**，见 §3） |

> 探测前该 USB-485 模块曾被其它程序以 19200 打开过，但不影响本次探测结论——本次对每个波特率都单独重开端口。

### 2.2 探测方法

1. **被动监听**：在 4800 / 9600 / 19200 下各静默监听 6 s，统计总线自发报文。
2. **波特率扫描**：4800 / 9600 / 19200 / 38400 / 57600 / 115200，8N1，逐档发送标准问询帧。
3. **地址扫描**：从站地址 0 ~ 255，逐地址发送 `FC03` 问询。
4. **功能码探测**：FC01/02/03/04/05/06/08/0x10/0x11/0x2B。
5. **寄存器映射**：逐块（64 寄存器/块）读取 0 ~ 2047，定位所有非零寄存器。
6. **动态性观测**：连续 15 s 采样，区分「静态配置寄存器」与「动态数据/RTC 寄存器」。
7. **文档交叉验证**：对两份厂家文档中的**全部报文样例**独立复算 CRC16。
8. **上位机取证**：从厂家配置软件 `RS-QXZ-M配置软件.exe` 提取协议相关字符串。

### 2.3 关键发现：总线空闲无自发报文

在 4800 / 9600 / 19200 下各监听 6 s，**收到 0 帧**。
说明：主机从站口平时**完全静默**，只在被问询时应答——即典型 Modbus RTU 从站行为，**不存在主站轮询流量**。
（这同时排除「误接到主机主站口 A1/B1 上、听到主机轮询下挂变送器」的可能。）

## 3. 结论速览：厂家文档 vs 实测

| 参数 | 厂家 RS-Modbus 规约 V2.0 | **本机实测** | 判定 |
| --- | --- | --- | --- |
| 串口波特率 | 4800 | **9600** | ❌ **文档错误/主机被改过** |
| 数据位/校验/停止位 | 8 / N / 1 | 8 / N / 1 | ✅ 一致 |
| 校验方式 | CRC（循环冗余） | CRC16/Modbus，低字节在前 | ✅ 一致 |
| 从站地址 = 通道号 | 是（1~32） | **是**（1~32 均应答，33+ 不应答） | ✅ 一致 |
| 支持功能码 | 仅 0x03 | **0x03 / 0x04 / 0x06 / 0x10** | ❌ **文档严重不全** |
| 寄存器表 | 仅 0000、0001 | **每个通道地址暴露 0~63 共 64 个寄存器** | ❌ **文档严重不全** |
| 时间寄存器 | 无 | **通道内 37~42 = 年/月/日/时/分/秒** | ❌ 文档缺失 |
| 异常应答 | 未说明 | **不支持的功能码/越界地址一律不应答（无异常帧）** | ⚠️ 文档缺失 |
| 总线空闲 | 未说明 | **完全静默** | ⚠️ 文档缺失 |
| 报文样例 CRC | —— | **1 处笔误（见 §10）** | ⚠️ 文档笔误 |

> **一句话结论**：本机当前处于 **RS-Modbus 规约**（从站地址 = 通道号），但**波特率是 9600 而非文档的 4800**，
> 且**功能码与寄存器空间远多于文档描述**。按文档 4800 直连将 100% 读不通。

## 5. 数据链路层帧格式

采用 **Modbus RTU**（与厂家文档一致）：

```
┌─────────┬─────────┬───────────────┬───────────────┬─────────┐
│ 地址码  │ 功能码  │   数据区       │    CRC16      │ 静默间隔 │
│ 1 字节  │ 1 字节  │   N 字节       │ 2 字节(低在前) │ ≥4 字符  │
└─────────┴─────────┴───────────────┴───────────────┴─────────┘
```

### 5.1 CRC16/Modbus

- 初始值 `0xFFFF`，多项式 `0xA001`（反射），**低字节先发**。
- 本机全部应答帧经独立复算，CRC 全部正确（见 §9 测试向量）。

参考实现：

```python
def crc16(data: bytes) -> bytes:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return bytes([crc & 0xFF, (crc >> 8) & 0xFF])
```

### 5.2 通用问询/应答结构

**读寄存器（FC03 / FC04）问询**（8 字节）：

```
地址码 功能码 起始地址高 起始地址低 寄存器数高 寄存器数低 CRC_L CRC_H
```

**读寄存器应答**：

```
地址码 功能码 字节数N 数据(N字节) CRC_L CRC_H
```

**写单寄存器（FC06）问询 / 应答**：报文相同（回显）。

**写多寄存器（FC16/0x10）问询**：

```
地址码 10 起始地址高 起始地址低 寄存器数高 寄存器数低 字节数 数据... CRC_L CRC_H
```

**写多寄存器应答**（8 字节）：

```
地址码 10 起始地址高 起始地址低 寄存器数高 寄存器数低 CRC_L CRC_H
```

## 6. 从站地址模型（实测）——**地址 = 通道号**

对地址 0 ~ 255 逐一发送 `FC03 起始0 数量2`，结果：

| 地址范围 | 结果 |
| --- | --- |
| `0x00`（广播） | **无应答** |
| `0x01 ~ 0x20`（1~32） | **全部应答**，且各地址寄存器内容不同 |
| `0x21 ~ 0xFF`（33~255） | **全部无应答** |

### 6.1 判定

- 若主机为**单地址标准 ModBus**，应只有菜单「3 ModBus 从地址」设置的那一个地址应答；实测 32 个地址全部应答。
- 各地址返回的是**各自独立的寄存器窗口**（通道参数不同，见 §8.3），且共享同一全局 RTC（§8.2）。
- 这与厂家 RS-Modbus 规约「**ModBus 从地址对应主机 32 个通道，通道 1 地址为 1、通道 2 地址为 2，依次类推**」**完全吻合**。

> ✅ **结论：本机当前为 RS-Modbus 规约。**
> 采集 20 路 = 对地址 1~20 各发一次问询，共 **20 次事务/轮**。
> 若改用标准 ModBus 规约，则只有单地址应答、可一次批量读回，二者需在主机菜单「ModBus 从规约」切换。

### 6.2 地址扫码原始结果（节选）

```
addr= 1 RX(9)=01 03 04 00 00 00 00 FA 33   OK
addr= 2 RX(9)=02 03 04 00 00 00 00 C9 33   OK
...
addr=32 RX(9)=20 03 04 00 00 00 00 CB 31   OK
addr=33 RX=                                TIMEOUT
```

## 7. 功能码支持矩阵（实测）

| 功能码 | 名称 | 实测结果 | 备注 |
| --- | --- | --- | --- |
| `0x01` | 读线圈 | **无应答（TIMEOUT）** | 不支持，且**不返回异常帧** |
| `0x02` | 读离散输入 | **无应答** | 不支持 |
| **`0x03`** | 读保持寄存器 | **正常** | 主力功能码 |
| **`0x04`** | 读输入寄存器 | **正常** | 行为与 0x03 相同 |
| `0x05` | 写单线圈 | **无应答** | 不支持 |
| **`0x06`** | 写单寄存器 | **正常**（回显） | 全部 0~63 寄存器均接受写入 |
| `0x07` | 读异常状态 | **无应答** | 不支持 |
| `0x08` | 诊断 | **无应答** | 不支持 |
| **`0x10`(16)** | 写多寄存器 | **正常**（回显地址/起始/数量） | — |
| `0x11` | 报告从站 ID | **无应答** | 不支持 |
| `0x2B/0x0E` | 读设备标识 | **无应答** | 不支持 |

> ⚠️ 厂家的 RS-Modbus 文档写「**本变送器只用到功能码 0x03**」——
> 实测本机**还支持 0x04、0x06、0x10**，文档严重不全。
>
> ⚠️ 与标准 Modbus 不同：**本机对非法功能码不返回异常应答（0x83 + 异常码），而是直接静默**。
> 因此软件必须用**超时**而不是异常帧来判定不支持的操作。

## 8. 寄存器映射（RS-Modbus 模式，实测）

### 8.1 通道寄存器窗口（每个从站地址 = 每个通道）

实测每个通道地址暴露 **64 个寄存器（0 ~ 63）**，其中：

| 寄存器 | 名称/含义 | 实测值 | 属性（实测） |
| --- | --- | --- | --- |
| `0` | 模拟量 **2** 原始值（16 位无符号） | 全 0 | 读/写（FC06 接受） |
| `1` | 模拟量 **1** 原始值（16 位有符号） | 全 0 | 读/写 |
| `2 ~ 7` | — | 0 | 读/写 |
| `8` | 通道状态/标志 | 恒 1 | 读/写 |
| `9` | 通道类型/参数 | 恒 19 | 读/写 |
| `10 ~ 11` | — | 0 | 读/写 |
| **`12`** | **通道参数 A**（含义未确认） | **逐通道不同**，见 §8.3 | 读/写 |
| `13` | — | 恒 1 | 读/写 |
| `14` | — | 0 | 读/写 |
| `15` | — | 恒 1 | 读/写 |
| **`16`** | **通道参数 B**（含义未确认） | **逐通道不同**，见 §8.3 | 读/写 |
| `17` | — | 恒 1 | 读/写 |
| `18` | — | 0 | 读/写 |
| `19` | — | 恒 1 | 读/写 |
| `20` | — | 恒 30 | 读/写 |
| `21` | — | 恒 3 | 读/写 |
| `22 ~ 30` | — | 0 | 读/写 |
| `31` | — | 恒 30 | 读/写 |
| `32` | — | 恒 30 | 读/写 |
| `33` | — | 恒 3 | 读/写 |
| `34` | 动态字段（疑似计时/计数） | 观测到 60 → 0 变化 | 读/写 |
| `35 ~ 36` | — | 0 | 读/写 |
| **`37 ~ 42`** | **全局 RTC：年/月/日/时/分/秒** | 见 §8.2 | 读/写 |
| `43 ~ 63` | — | 0 | 读/写 |
| `64 ~ 2047` | 保留/未用 | **恒 0** | 越界亦返回 0，不报异常 |

> **重要**：厂家 RS-Modbus 文档的寄存器表**只列了 0 和 1 两个寄存器**，
> 实测本机每个通道实际暴露 **64 个寄存器**，文档严重缺项。
>
> **重要**：实测**未发现**标准 ModBus 文档中描述的「处理值浮点区（64~191）」「上下限（300~555）」「偏差（556~683）」
> 「时间（684~689）」「存储控制（690~695）」「继电器（696~703）」——
> 在 RS-Modbus 模式下这些地址**全部恒为 0**。两套规约的寄存器空间**不相同**，不可混用。

### 8.2 全局 RTC（通道内 37 ~ 42，全通道共享）

| 寄存器 | 含义 | 取值范围（实测） |
| --- | --- | --- |
| `37` | 年 | 2026 |
| `38` | 月 | 9 |
| `39` | 日 | 20 |
| `40` | 时 | 21 |
| `41` | 分 | 0 ~ 59 |
| `42` | 秒 | 0 ~ 59 |

实测 15 s 动态观测：**仅 37~42 随时间变化**（分/秒推进），全部 32 个通道读取到**同一时间**，证明 RTC 为全局。

| 通道(地址) | reg12 | reg16 | 通道(地址) | reg12 | reg16 |
| --- | --- | --- | --- | --- | --- |
| 1 | 999 | 3392 | 11 | 3392 | 999 |
| 2 | 1000 | 140 | 12 | 999 | 10000 |
| 3 | 200 | 999 | 13 | 999 | 1000 |
| 4 | 50880 | 999 | 14 | 999 | 1000 |
| 5 | 999 | 40000 | 15 | 999 | 1000 |
| 6 | 999 | 1000 | 16 | 999 | 35000 |

> 这与「本机启用 20 路通道、其余 12 路未配置」高度吻合，可佐证地址 = 通道号的判定。
> reg12/reg16 的**确切语义未确认**（疑为传感器型号/量程/序列号），需厂家确认。

### 8.4 原始值读取（本项目的核心）

按厂家 RS-Modbus 文档，通道原始值即：

- `reg0` = 模拟量 2 原始值（16 位**无**符号）
- `reg1` = 模拟量 1 原始值（16 位**有**符号）

**实测当前所有通道 reg0/reg1 均为 0**（现场未接传感器或通道未采集到数据）。
该布局与文档一致，但**本机采样时刻无数值**，无法验证 A/B 系数换算，需现场接传感器后复测。

> 工程量换算：`显示值 = 原始值 × 系数A + 系数B`（系数在主机菜单「通道参数」中设置，不在从站寄存器中直接可读）。

## 10. 边界与异常行为（实测）

| 场景 | 实测行为 | 对软件的要求 |
| --- | --- | --- |
| 非法功能码（0x01/0x02/0x05/0x08/0x11/0x2B） | **静默，无异常帧** | 以**超时**判定失败 |
| 坏 CRC 的帧 | **静默（被丢弃）** | 正常 Modbus 行为 |
| 噪声帧 | 静默 | — |
| 广播地址 0 | 静默 | 不支持广播 |
| 地址 ≥ 33 | 静默 | 地址扫描用于发现在线通道 |
| **寄存器数 ≥ 125** | **应答字节数回绕**：`字节数 = (寄存器数×2) mod 250` | **单次读取必须 ≤ 124 个寄存器** |
| 起始地址越界（如 7000） | **不报异常**，返回 0 | 不要依赖越界异常做探测 |

### 10.1 「250 字节回绕」实测数据

| 请求寄存器数 | 期望应答字节数 | 实测应答字节数 |
| --- | --- | --- |
| 40 | 80 | 80 ✅ |
| 64 | 128 | 128 ✅ |
| 80 | 160 | 160 ✅ |
| **125** | 250 | **0** ❌ |
| **126** | 252 | **2** ❌ |
| **128** | 256 | **6** ❌ |
| **200** | 400 | **150** ❌ |

> **规避方法**：单次读寄存器数 **≤ 124**；本项目 20 路若走标准规约，80 个寄存器（165 字节）
> 在限制内，可一次读完，**无需分片**。

## 11. 时序实测（COM3 @ 9600 8N1）

| 事务 | 帧长 | min | avg | p95 | max |
| --- | --- | --- | --- | --- | --- |
| 读 2 寄存器（应答 9 B） | 8 B | 26.6 ms | **32.4 ms** | 71.2 ms | 88.3 ms |
| 读 64 寄存器（应答 133 B） | 8 B | 155.7 ms | **174.3 ms** | 247.8 ms | 297.5 ms |
| 读 80 寄存器（应答 165 B） | 8 B | 187.5 ms | **203.4 ms** | 219.3 ms | 267.5 ms |

> 耗时基本由 **9600 bps 串行传输时间**决定（165 B 往返 ≈ 180 B × 10 bit ÷ 9600 ≈ 188 ms）。
> **对 LoRa 链路的意义**：电台串口速率若为 9600，则一帧的串口时间本身就接近 200 ms，
> 再叠加 LoRa 空中时间 + LBT + 重传，RTT 会显著增大。建议电台串口速率 ≥ 19200，或放宽超时。

## 12. 厂家文档勘误（对全部样例独立复算 CRC16）

### 12.1 CRC 复算结果

| 来源 | 报文 | 文档 CRC | 复算 CRC | 结论 |
| --- | --- | --- | --- | --- |
| RS-Modbus 举例1 问询 | `02 03 00 00 00 02` | C4 38 | C4 38 | ✅ |
| RS-Modbus 举例2 问询 | `0C 03 00 00 00 02` | C5 16 | C5 16 | ✅ |
| RS-Modbus 举例1 应答 | `02 03 04 02 92 FF 9B` | 69 3D | 69 3D | ✅ |
| RS-Modbus 举例2 应答 | `0C 03 04 02 92 FF 9B` | 86 FD | 86 FD | ✅ |
| 标准规约 读原始值 问询 | `05 03 00 02 00 04` | E4 4D | E4 4D | ✅ |
| 标准规约 读原始值 应答 | `05 03 08 00 ED 02 7B 00 E0 00 F9` | 99 B5 | 99 B5 | ✅ |
| 标准规约 读处理值 问询 | `05 03 00 BC 00 04` | 84 69 | 84 69 | ✅ |
| 标准规约 读处理值 应答 | `05 03 08 41 E3 A5 E3 42 82 B1 AA` | 0A 89 | 0A 89 | ✅ |
| 标准规约 校时 设置 | `05 10 02 AC 00 06 0C 07 E1 00 03 00 1C 00 09 00 3B 00 20` | E4 2B | E4 2B | ✅ |
| **标准规约 校时 应答** | 文档写 `05 10 02 6C 00 06` | 80 16 | **80 2A** | ❌ **文档笔误** |
| 标准规约 校时 应答（正确） | `05 10 02 **AC** 00 06` | 80 16 | **80 16** | ✅ |
| 标准规约 继电器 设置 | `05 06 02 BA 00 01` | 69 D3 | 69 D3 | ✅ |

**勘误 1**：标准规约文档 §5-3）校时应答帧把起始地址 `02 AC` 误写成 `02 6C`。
正确帧应为 **`05 10 02 AC 00 06 80 16`**（文档自身给出的 CRC `80 16` 也只对 `02 AC` 成立）。

**勘误 2**：标准规约文档 §5-4）继电器示例，帧内 CRC 为 `69 D3`（正确），
但下方「详解」文字写成 `69 EF`，属排版笔误。

**勘误 3**：标准规约文档 §5-1）读原始值示例中，寄存器编号解说错位
（把 `0002` 起读的 4 个寄存器解说成「2 号寄存器 / 3 号寄存器…」且数值对应混乱），
虽不影响协议本身，但极易误导开发。

### 12.2 实质性差异汇总

| # | 文档说法 | 实测 | 影响 |
| --- | --- | --- | --- |
| 1 | 波特率 4800 | **9600** | **按 4800 直连完全读不通** |
| 2 | 仅支持功能码 0x03 | 支持 0x03/0x04/0x06/0x10 | 写操作/读输入寄存器可用 |
| 3 | 寄存器仅 0000、0001 | 每通道 0~63 共 64 个寄存器 | 文档缺项，隐藏功能未知 |
| 4 | 未提时间寄存器 | 通道内 37~42 = RTC | 可做主机对时 |
| 5 | 未提异常行为 | 非法操作静默，无异常帧 | 软件须超时判定 |
| 6 | 未提读取上限 | ≥125 寄存器回绕 | 读取 ≤124 寄存器 |

## 13. 对本项目采集实现的影响与建议

### 13.1 直接结论

1. **物理参数必须更正**：主机从站口实际为 **9600 8N1**，不是说明书/规约文档的 4800。
   需求文档 §5.1 的「485 直连 4800」与 §10-A1 的默认值需更新为 **9600**（现场菜单「17 485 从站波特率」复核）。
2. **本机当前为 RS-Modbus 规约**：地址 = 通道，读 20 路 = **20 次事务/轮**。
   需求文档 §4.3「RS-Modbus 在 10 s 周期下不可行」的结论**在本机实测下依然成立且更紧迫**。
3. **建议切换为「标准 ModBus 规约」**（若主机支持，见待确认项 C）：
   单地址 + 批量读，一轮 1~2 次事务即可完成，且可读「处理值」（省去 A/B 换算）。

### 13.2 采集参数建议（RS-Modbus 模式）

| 参数 | 485 直连 | DR206-L LoRa |
| --- | --- | --- |
| 波特率 | 9600 | 电台串口侧按模块实际（建议 ≥19200） |
| 数据格式 | 8N1 | 8N1 |
| 每轮事务数 | 20（地址 1~20） | 20 |
| 单事务字节 | 8 B 问询 / 9 B 应答 | 同 |
| 响应超时 | 300 ms | 3000 ms（可配） |
| 帧间隔 | ≥ 10 ms | 50 ~ 100 ms |
| 应用层重试 | 1 ~ 2 次 | 1 ~ 2 次（避免与电台重传叠加） |
| 单次读寄存器数 | ≤ 124 | ≤ 124 |

### 13.3 收帧策略（建议）

- **按预期长度收帧**：FC03 应答 = `3 + 字节数 + 2`；读到该长度即返回。
- **不依赖异常帧**：本机不支持的操作**静默**，需以超时判定。
- 打开/重连后**清空接收缓冲区**。
- 严格一问一答，禁止连续快发。
