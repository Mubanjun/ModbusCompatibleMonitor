# 现场部署与验收手册（无损替换仁科环境监测平台）

> 面向现场实施人员：按本手册在一台新的监测主机/工控机上完成部署、数据迁移与逐条验收。
> 需求条目对应的自动化脚本见 `docs/需求实现核查表.md`；本手册讲的是**现场怎么做、看到什么算通过**。

## 一、交付物清单

## 三、部署步骤（15 分钟）

```powershell
# 1) 解压发布包到安装目录，例如 D:\jdrk
#    目录内应有：continew-admin.jar、runtime\、watchdog.properties、start-*.ps1
cd D:\jdrk

# 2) 改配置（数据库/Redis 地址与口令；生产参数已内置：关闭 SQL 逐条日志、日志级别 INFO）
notepad watchdog.properties     # app.args 里的 ${DB_HOST:...} 可用环境变量注入，也可直接写死

# 3) 启动（看门狗拉起后端，进程异常会自动重建）
.\start-watchdog.ps1 -Jar continew-admin.jar -Config watchdog.properties

# 4) 验证（看到 healthy=true 即通过）
curl http://127.0.0.1:8000/monitor/watchdog/heartbeat
```

- 前端入口：`http://<主机IP>:8000`，初始超管 `admin`；
  - 前端已打进同一个 jar（`build-all.ps1` 先构建 `frontend/dist`，再由后端 `processResources` 并入 `classpath:/static/`），**不需要另外部署 nginx**；
  - 前端接口地址为「同源相对路径」（`frontend/.env.production` 的 `VITE_API_PREFIX` 留空），因此换 IP/换端口都不用重新打包；
  - `vue-router` 为 history 模式：直接访问或刷新 `/env/device` 这类深链接由 `SpaForwardFilter` 回退到 `index.html`；接口调用的 404 语义不变（仍返回「请求 URL 不存在」的 JSON）；
  - 若现场实测打不开界面，先查 `curl -I http://127.0.0.1:8000/index.html` 是否 200，再看 `sa-token.extension.security.excludes` 里是否包含 `/static/**`；
- 若要开机自启：`tools/install-autostart.ps1`（计划任务或「启动」文件夹，二选一，支持 `-DryRun` 预演）；
- Linux 用 systemd：`ExecStart=/opt/jdrk/runtime/bin/java -cp continew-admin.jar -Dloader.main=top.continew.admin.watchdog.WatchdogMain org.springframework.boot.loader.launch.PropertiesLauncher --config=watchdog.properties`；
- 停机务必用 `tools/stop-monitor.ps1`（先走优雅停机接口，再兜底强杀），不要直接拔电或 taskkill。


### 3.2 一键现场验收（推荐先跑这个）

```powershell
pwsh -File tools/field-acceptance.ps1                       # 默认 admin/admin123@127.0.0.1:8000
pwsh -File tools/field-acceptance.ps1 -Base http://192.168.74.10:8000 -User admin -Password 你的口令
```

不依赖 Python/SSH，只用本机 HTTP 接口，逐项打印 PASS/FAIL（共 **20 项**）：心跳与自检、版本、登录（口令 RSA 加密链路）、
采集运行与拓扑（端口/设备/轮次）、暂存积压与丢弃、实时数据、看门狗自检与集群角色、上报通道与目标、报警记录、
上报死信、历史数据 CSV 导出（2 分钟窗口）、报警规则、报警通知记录、继电器写使能、继电器审计、备份状态、单表 SQL 导出，
以及「运行日志里没有裸手机号（脱敏生效）」；退出码 0 表示全部通过。
本仓库开发环境实测 **20/20**（脱敏项在注入一条带手机号的日志后仍为 0 个裸手机号、1 个打码样本）。

### 3.1 安全加固（建议现场照做）

| 项 | 做法 |
| --- | --- |
| 管理端口白名单 | 默认只放行回环 + RFC1918 私网；要收紧就加 `--jdrk.security.allowed-cidrs=192.168.74.0/24,127.0.0.1/32` |
| 管理端 HTTPS | 用 `dist/runtime/bin/keytool` 生成 PKCS12 证书，启动加 `--server.ssl.enabled=true --server.ssl.key-store=file:./server.p12 --server.ssl.key-store-password=***` |
| 上报/数据库加密 | MQTT 目标 `tls=true`；数据库 URL 加 `useSSL=true&requireSSL=true`（自签证书再指信任库） |
| 敏感字段 | 日志/诊断包/导出已自动脱敏（手机号、身份证、邮箱、银行卡），无需配置 |
| 数据库口令 | 生产库口令不要用默认值；`watchdog.properties` 建议只放环境变量引用，避免明文入库房 |

## 四、数据迁移与无损替换

1. **迁移向导**：管理端「系统工具 / 迁移」→ 填原仁科库连接 → 检测表结构（自动识别 `tbhistory/tbalarm/...`）→
   先「导入设备」再做「历史数据迁移」（支持时间范围、幂等、冲突策略、进度与错误定位）；
2. **验收口径**：迁移完成后用向导自带的「一致性校验」比对本系统与源库的窗口行数（同设备子集）；
3. **自包含回退**：`tools/rollback-self-contained.ps1 -DryRun` 先预演（不改进程/服务，输出就绪度与将要执行的步骤），
   确认无误再去掉 `-DryRun` 执行；回退范围是**平台自身**——模式切回 OFF、（可选）恢复自有备份、停止本平台并释放设备句柄，
   设备接管由业主按其现场规程执行；**本平台不启动、不调用、不依赖任何第三方原软件**（防侵权口径）；
4. **割接建议**：低峰期做一次「停仁科 → 迁移 → 核对 → 切换采集」；原库保留只读一段时间再离线归档。
## 五、逐条验收清单（现场照做）

| 需求域 | 现场操作 | 期望结果 | 没有真实设备时怎么造 |
| --- | --- | --- | --- |
| 通讯与采集（Modbus TCP） | 建端口 `127.0.0.1:15020` + 设备（MODBUS_TCP / 从站 1 / 间隔 2s）+ 3 路通道 | 实时数据页出现 pH=7.42、温度=19.9、电导率=11457，质量 GOOD | `node tools/modbus-tcp-sim.mjs --port 15020 --unit 1 --holding 742,199,11457` |
| 通讯与采集（Modbus RTU/485） | 建端口 COM3/9600 + MODBUS_RTU 设备（从站 1） | 485 采集到三路通道，信令页有 OUT/IN 帧且为 `01 03` 开头 + CRC | HHD 虚拟串口对 + `python _extract/rtu_slave.py COM12 9600 1,2` |
| RS-Modbus 协议 | 同端口改成 RS_MODBUS + 从站 2 | 采集与 RTU 一致，线上帧为 `02 03` 开头 | 同上（从站脚本同时服务 1、2） |
| 三级间隔/超时重试 | 设备间隔改 1 秒、超时 500ms、从站地址改成不存在的 9 | 信令页能看到重试与超时；实时值质量变 BAD/COMM_ERROR；设备状态 COMM_ERROR | 直接改配置即可复现 |
| 数据落地与查询 | 历史数据页按时间/设备/要素筛选、翻页、导出 CSV/Excel（可切 GB18030） | 行数与筛选一致、导出文件能正常打开且中文不乱码 | 用模拟器持续采几分钟 |
| 暂存缓冲与断网续传 | 停掉数据库（或断网）→ 观察暂存状态 → 恢复数据库 | 采集不中断，`pendingCount` 增长；恢复后归零、`droppedCount=0` | 停 MySQL 服务 1 分钟 |
| 报警引擎 | 建规则（>30 报警、<20 恢复、防抖 3 次、通知选站内/邮件）→ 把寄存器改成超限值 | 报警记录产生、通知发出、恢复后自动闭环；抖动不会刷屏 | 改模拟器寄存器值（`--holding`） |
| 上报引擎（MQTT/DB/HTTP） | 建三类目标 + 规则（1s / 5s）→ 看目标侧 | Broker 收到 JSON 报文（含 `schemaVersion`）；目标表新增行；HTTP 收到 POST | `node tools/mqtt-broker-sim.mjs --port 18830 --verbose` |
| 上报重试与死信 | 把 MQTT 端口改成错的、或停掉 Broker | 死信页出现记录（含原因与报文），恢复后可「人工重放」且状态变 REPLAYED | 停掉 Broker 即可 |
| 同步引擎 | 新建全量/增量同步任务（表 `tbhistory,tbalarm`），试冲突策略与暂停续传 | 目标表行数与源窗口一致；冲突明细可查；水位线建立；重复同步幂等 | 源库用现场仁科库，或先造几张同构表 |
| 继电器控制 | 继电器页读状态 → 单路闭合/断开 → 回读 | 8 路状态正确、回读一致、审计记录 SUCCESS（485 需真实继电器板） | 无继电器板时跳过写操作，只验读状态与审计 |
| 导入导出与备份 | 导出历史 CSV/单表 SQL；创建备份包（可选加密）→ 校验 → 恢复 | 文件可回灌、校验通过、恢复后行数一致 | 用模拟器数据即可 |
| 日志与诊断 | 在线切换日志级别 → 重启 → 导出诊断包 | 级别重启后保持；日志按模块分文件；诊断包内容已脱敏（无原始手机号/邮箱） | 直接操作即可 |
| 看门狗与自愈 | 直接 Kill 后端进程（不要用停机接口） | 15~30 秒内自动拉起、心跳恢复；`/monitor/watchdog/status` 有 CRASH 与重启记录 | 直接 `Stop-Process -Id <后端 pid>` |
| 单实例控制 | 在平台运行中再次启动一个实例 | 第二个实例立即退出并提示「已有实例在运行」 | 再执行一次启动命令 |
| 安全加固 | 用非白名单 IP 访问管理端口；HTTPS 端口做证书链校验；导出/日志搜手机号 | 前者 403 且日志留痕；HTTPS 证书校验通过；导出/日志里只有打码值 | 用另一台机器或用主机内网卡地址访问 |
| 多实例（可选） | 两台机器连同一 MySQL + Redis 启动，均开 `--jdrk.cluster.enabled=true` | `/monitor/watchdog/status` 显示一 LEADER 一 FOLLOWER；停掉主节点后从节点在租约时间内接管 | 单机可用两个工作目录 + 不同端口演练 |
| 容量与性能 | 按核查表 PERF 条目跑 `_extract/verify_capacity.py prepare/check/cleanup`（需 Python + SSH 的验收机） | 满配矩阵加载、采样持续、dropped=0、积压可控 | 仅验收机需要该脚本 |

| 模块插拔（V1.4） | 关闭 `jdrk.modules.alarm.enabled` 与 `jdrk.modules.analytics.enabled` 后重启 | 应用可启动、菜单消失、前端不加载对应 chunk、其它模块/采集正常；重新开启恢复 | 修改启动参数，无需改 jar |
| 设备地图（V1.4） | 配置 `MAP/AMAP_JS_KEY` 与 `AMAP_SECURITY_CODE`（或故意留空）→ 打开 `/env/device-map` | 有 Key：分组筛选、状态着色、400+ 点位聚合、点击卡片；无 Key/无公网：坐标清单 + 本地静态底图，不白屏 | 无 Key 时直接验降级；400 点位用压测夹具 |
| 位置维护（V1.4） | 设备编辑填经纬度/地图点选；准备 400 行 CSV 导入 | 合法坐标保存并审计；非法经/纬度被拒；400 台批量 ≤5s、幂等、错误行有明细 | 构造重复行与越界坐标 |
| 预测预留（V1.4） | 关闭 `jdrk.modules.predict.enabled` 或调用预测接口 | 返回明确「未启用」；无 500、无重复异常日志；其它模块不受影响 | 不写算法，只看契约/Noop |
| RFC2217（V1.4） | 端口类型选 `RFC2217`，填 `host:port` + 串口参数；socat+rfc2217_server+rtu_slave 造 4×10 从站 | 单端口采集成功；kill 服务端转通讯异常并自动重连；波特率不匹配有 WARN；40 台成功率 ≥99% | 见 SRS §12 与压测脚本 |
| 400 传感器 × 1 小时（V1.4） | 跑 `P-*` 隔离夹具：160 TCP + 80 RTU + 40 ASCII + 40 RS + 40 MQTT + 40 RFC2217，≥60 分钟 | 400 台、5xx=0、自检不红、采样成功率 ≥99%、无每秒刷屏、内存无单调增长；中段 kill -9 <60s 恢复；产物齐全 | 结束后按前缀清理并回对行数 |
| 数据异常与运行时长（V1.4） | 强杀后端一次；逐页搜 `9223372036854775807`/`NaN`/`undefined`/`null`/`Infinity` | 三者时长各自正确；页面无哨兵值/空值字面量；缺心跳显示明确缺值文案 | 用浏览器渲染文本与接口响应双向检查 |

## 七、排障速查

| 现象 | 先看什么 |
| --- | --- |
| 心跳 `healthy=false` | 心跳接口里的 `checks` 逐项（数据库/采集调度/本地暂存/Redis/磁盘空间），按失败项提示处理 |
| 一直 COMM_ERROR / 端口打不开 | 端口配置（地址/波特率）→ 设备从站地址与协议 → 串口是否被别的程序占用（探测接口会明确提示「串口被占用」） |
| 实时值没有数据 | 采集是否在运行、设备/通道是否启用、寄存器地址与数据类型系数是否正确 |
| 上报没有报文 | 目标配置（host/port/tls/主题/表名）、规则是否启用与间隔、死信页里的失败原因 |
| 上报积压 | 目标库吞吐是否低于采集速率（缓冲上限 10 万，超出会丢最旧并记 `droppedItems`） |
| 访问被拒 403 | 来源白名单 `jdrk.security.allowed-cidrs`（应用日志里有「拒绝来源」记录） |
| 日志占磁盘 | 启动参数必须带 `--logging.level.top.continew.admin=INFO` 且用 MySQL 驱动（不要 dev profile）；日志总占用上限默认 2GB |
| 导出文件很大/很慢 | 导出端点按**时间窗 + 设备/节点/模拟量**过滤后流式输出，**没有 limit 参数**；不传过滤条件就是整表（5 万行约 4.5MB）。导出是流式的：实测连续 15 次整表导出后后端 RSS 稳定在 ~920MB（`-Xmx1g`），不会越导越大 |
| 服务起不来 | `logs/continew-admin.out.log` 尾部 + 单实例锁提示 + 数据库/Redis 可达性 |
