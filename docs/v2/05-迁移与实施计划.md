# v2 迁移与实施计划（基线草案）

> 从 v1（Spring Boot 单机版）迁移到 v2（ThingsPanel 魔改 + Rust 边缘 + 级联），包含工作分解、里程碑与风险。

---

## 1. 总体路线

| 阶段 | 周期 | 目标 | 出口条件 |
|---|---|---|---|
| P0 决策与技术验证 | 3~4 周 | 法务确认、1000 站模拟压测、模板 PoC | 压测达标；许可结论书面化 |
| P1 底座与前端分离 | 6~8 周 | Fork ThingsPanel、白标、模板导入、Modbus 打通 | 模板导入即可采数并入库 |
| P2 边缘 Agent | 8~10 周 | Rust Agent：串口/raw/RFC2217/MQTT、缓存续传 | 断网 7 天补传成功率 100% |
| P3 级联服务 | 8~10 周 | 三级/星型、配置下发、命令、补传、鉴权 | 3000 站模拟稳定 24h |
| P4 多租户与数据 | 6~8 周 | RBAC、区域权限、时序查询、报表 | 越权 403；查询 P95 达标 |
| P5 验收与迁移 | 4~6 周 | 压测、信创、v1 数据迁移、演练 | 验收清单全绿 |

人力建议：4~6 人（后端 2、前端 1、边缘/Rust 1、测试/运维 1）。

---

## 2. 工作分解（WBS）

### P0 技术验证

1. 省中心最小集群（Broker + PG + 时序库）；
2. 1000 站模拟器（NanoMQ + 批量上报）；
3. 验证主题/桥接/防环/补传；
4. ThingsPanel 模板机制与插件 SDK PoC；
5. 许可与法务：ThingsPanel 多租户自研、TDengine、Neuron、EMQX BSL。

### P1 底座

- 白标（Logo/标题/主题/版权）；
- 模板规范落地（导入、校验、版本、导出）；
- Modbus RTU/TCP 模板 + 模拟器联调；
- 站点/区域模型替换原「项目/分组」；
- 前端改造：监测大屏、站点树、设备详情。

### P2 边缘

- 串口抽象（485/232/TTL）、raw TCP、RFC2217、Modbus TCP；
- 模板渲染与点位采集、质量码；
- SQLite 队列、断网续传、限速回放；
- 远程配置拉取、固件升级、健康上报；
- ARM64 交叉编译与现场安装包。

### P3 级联

- 主题与 ACL、mTLS、JWT；
- 单向桥接/Cluster Linking、防环；
- 配置版本下发与回滚；
- 命令路由、审批、审计、回执；
- seq 缺口检测与补传调度。

### P4 数据与权限

- 区域/站点数据权限（API 强制注入）；
- 时序查询、降采样、聚合、导出；
- 报警规则与通知、报表；
- 开放 API 与配额。

### P5 验收

- 3000 站 × 24h 压测；故障注入；
- 信创（麒麟/统信 + ARM64）；
- v1 数据迁移（设备/通道/历史）；
- 现场演练与回退。

## 3. v1 → v2 数据迁移

| v1 | v2 | 说明 |
|---|---|---|
| `biz_port` | `station`/`channel` | 端口按站点归并 |
| `biz_device` | `device` | 保留名称/地址/协议/位置 |
| `biz_channel` + `biz_sensor` | `point` | 要素、单位、缩放、量程合并 |
| `biz_sensor_reading` | `reading` | 时间戳 + 值 + 质量码 |
| `biz_alarm_*` | `alarm_record` | 规则迁移，历史保留 |
| `sys_user/role/menu` | 平台用户/角色 | 权限模型重建 |
| 仁科 `rkmonitor` | 北向适配器 | 保留输出能力 |

迁移步骤：
1. 结构映射与试迁移（脱敏库）；
2. 双跑：v1 继续采集，v2 影子入库，比对 7 天；
3. 切换：站点逐个切换上报地址，保留回退开关；
4. 回退：DNS/配置切回 v1，数据不丢。

## 4. 验收标准（摘）

| 编号 | 项 | 标准 |
|---|---|---|
| AC-V2-01 | 模板接入 | 导入模板后 5 分钟内采到数 |
| AC-V2-02 | 断网续传 | 断网 7 天恢复后 30 分钟内追平，无丢点 |
| AC-V2-03 | 级联 | 三级链路 24h 稳定，无回环/重复 |
| AC-V2-04 | 权限 | 跨区域访问 403；导出同权限 |
| AC-V2-05 | 规模 | 3000 站模拟，5xx=0，P95 达标 |
| AC-V2-06 | 命令 | 下发-回执-审计闭环，超时进死信 |
| AC-V2-07 | 部署 | 离线镜像一键部署；ARM64 可用 |
| AC-V2-08 | 迁移 | 历史数据一致率 ≥99.9% |

## 5. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 许可变更（EMQX/TDengine/Neuron） | 成本或返工 | P0 法务结论；优先宽松许可 |
| ThingsPanel 改造成本超预期 | 延期 | 先 PoC 2 周，评估再承诺 |
| 多租户需求变更 | 返工 | 首版按区域权限，预留 tenant_id |
| 现场协议差异 | 接入失败 | 模板 + 插件 + 现场摸底 |
| 断网补传雪崩 | 省中心过载 | 背压 + 限速 + 丢旧保新 |
| 团队 Rust 经验不足 | 边缘延期 | 先做最小 Agent，复用现成库 |

---

## 6. 与现有资产的关系

- v1 的 Docker 编译测试流水线可复用于 v2 镜像构建；
- v1 的验收脚本思路（菜单一致性、数据权限）迁移为 v2 的 API 契约测试；
- v1 的需求编号保留，在 SRS v2 中建立「旧编号 → 新章节」映射，避免追溯断裂。
