# 需求规格说明书 v2（变更稿）

> 本文是 [v1.4 SRS](../仁科兼容环境监测平台需求规格说明书.md) 的**变更稿**：只列出变化或新增的章节。
> 未列出的章节（如 §4.2 TUI、§4.7 继电器、§4.15 导入导出等）**沿用 v1.4**，待 v2 定稿时再逐章确认。
>
> **状态**：基线草案，对应 ADR-001~007（见 [00-架构决策记录](00-架构决策记录.md)）。标 ⚠ 的条目依赖尚未确认的假设（A1~A5）。

## 0. 变更摘要

| 主题 | v1.4 | v2 |
|---|---|---|
| 部署形态 | 单机 jar + 内置 Vue 静态资源 | 前后端分离：SPA 独立托管 + API `/api/v1` |
| 接入模型 | 串口/TCP/MQTT 客户端 | 站点边缘 → 区域 → 省的多级 / 星型接入 |
| 设备抽象 | 端口→设备→通道 | region→station→device→point + 模板 |
| 消息 | 平台内直连设备 | MQTT 5 为主，主题规范化，断网续传 |
| 存储 | MySQL + SQLite 暂存 | PostgreSQL + 时序库（TimescaleDB/IoTDB）+ Redis |
| 技术栈 | Java 21 + Spring Boot | Go（ThingsPanel 改造）+ Rust（边缘）+ Vue3 |
| 运维 | TUI + 自研看门狗 | Web 控制台 + Prometheus/Grafana；看门狗保留、TUI 可选 |
| 规模 | 100 台主机基线 | 3000 站 / 30 万测点 / 3000~5000 msg/s |

### 假设（未确认）

| 编号 | 假设 | 影响 |
|---|---|---|
| A1 | 业务底座采用 ThingsPanel（Apache-2.0）魔改 | 决定 60% 代码来源 |
| A2 | 多租户首版按「区域行政层级」实现，预留 `tenant_id` | 决定权限模型 |
| A3 | 消息层走零许可路线（VerneMQ 或 EMQX 5.8.x） | 决定级联实现 |
| A4 | 时序库用 TimescaleDB 或 Apache IoTDB，不用 AGPL 的 TDengine | 决定存储 |
| A5 | 规模按 3000 站 / 30 万测点 / 60s 打包上报，1s 原始值只留站端 | 决定容量与采样 |

## 1. 运行环境（改写 v1.4 §2.5）

| 项 | v2 要求 |
|---|---|
| 中心服务端 | Linux x86_64/ARM64（Ubuntu 22.04+/麒麟/统信）；容器化优先 |
| 边缘节点 | ARM64 或 x86_64 Linux；内存 ≥512MB，磁盘 ≥16GB（缓存 7~30 天） |
| 边缘运行时 | Rust Agent 单二进制（无 JVM）；或第三方数采网关（MQTT/Modbus TCP） |
| 浏览器 | Chrome/Edge 100+、Firefox 100+；不要求插件 |
| 网络 | 站点↔区域↔省 可经 4G/专线；允许 NAT；断网需本地自治 |
| 时间同步 | 站点 NTP/北斗，偏差 >5s 告警并校时 |
| 信创 | 中心与边缘均需 ARM64 镜像；数据库/中间件在信创清单内可选 |

## 2. 总体架构（改写 v1.4 §3）

### 2.1 逻辑架构（引用 [01-总体架构](01-总体架构.md)）

四层：展示层（SPA/大屏/开放 API）→ 应用层（ThingsPanel 改造 + 级联服务）→ 消息与存储层（Broker/PG/TSDB/Redis）→ 接入层（区域 Broker / 站点 Agent / 设备）。

### 2.2 部署拓扑

- L0 站点：Agent + NanoMQ + 本地队列；
- L1 区域：Broker 集群 + 级联服务 + 本地 TSDB；
- L2 省中心：Broker 集群 + API 多副本 + TSDB 主库 + 级联服务；
- L3 灾备/上级：同构单向复制；
- 星型：重点站直连 L2，复用同一主题与 ACL。

### 2.3 技术选型（替代 v1.4 §3.3 相关行）

| 层 | v2 选型 | 备注 |
|---|---|---|
| 业务平台 | ThingsPanel 改造（Go） | ADR-001 |
| 前端 | Vue3 + TS（独立构建） | 前后端分离 |
| 边缘 | Rust（tokio/rumqttc/serde/SQLite） | ADR-002 |
| 消息 | MQTT 5；VerneMQ / EMQX 5.8 / EMQX 6 企业版 | ADR-003 |
| 时序 | TimescaleDB / Apache IoTDB | ADR-004 |
| 元数据 | PostgreSQL 15+ | — |
| 缓存 | Redis 7 / Valkey | — |
| 接入网关 | OpenResty（L4/WS/限流） | ADR-005 |
| 运维 | Prometheus + Grafana + Loki | ADR-007 |
| 容器 | Docker Compose（站点/单机）、K8s（省中心可选） | — |

### 2.4 进程模型（改写 v1.4 §3.2）

| 进程 | 位置 | 职责 |
|---|---|---|
| API 服务 | 省/区域 | 业务、权限、模板、查询（无状态，多副本） |
| 级联服务 | 省/区域 | 主题桥、配置、命令、补传、审计 |
| Broker | 各级 | 接入、会话、离线队列、级联 |
| Rust Agent | 站点 | 采集、模板、缓存、续传、本地告警 |
| 看门狗 | 单机部署 | 进程守护（保留）；容器部署用 restart policy |

## 5. 数据需求（改写 v1.4 §6）

### 5.1 关系模型（PostgreSQL）

| 表 | 说明 |
|---|---|
| `region` | 区域树（省/市/县） |
| `station` | 站点（编码、区域、坐标、状态） |
| `device` | 设备实例（station_id、template_id、地址） |
| `point` | 测点（device_id、code、单位、量程、缩放） |
| `template` / `template_version` | 模板与版本（JSONB） |
| `alarm_rule` / `alarm_record` | 报警 |
| `command` / `command_log` | 命令与审计 |
| `user/role/menu/permission` | 权限 |
| `tenant`（预留） | 多业主时启用 |

### 5.2 时序模型

- 超级表/measurement：`reading(station, device, point, ts, value, quality)`；
- 分区：按天/月；TTL：原始 90 天，聚合 3 年（省中心）；
- 幂等键：`(station, device, point, ts)`；
- 降采样：1min/5min/1h 物化或连续聚合。

### 5.3 保留与容量

| 层级 | 原始 | 聚合 |
|---|---|---|
| 站点 | 1s，7~30 天 | 1min，90 天 |
| 区域 | 1min，30~90 天 | 5min/1h，1 年 |
| 省中心 | 1min，90 天 | 5min/1h，3 年 |
